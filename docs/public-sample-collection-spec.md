# Public Sample Collection Spec

## 目的

本规范用于指导项目收集、整理和维护公开样本，作为以下能力的基础资产：

- 政策解读
- 正式润色
- 报告提纲生成
- PPT 提纲生成
- 风格稳定化
- 表达校准
- 测试与回归验证

本项目仅允许使用：
- 公开可访问的政策、监管、披露、研究、演讲、报告材料
- 项目创建者明确提供且确认可使用的公开内容

不得纳入：
- 内部材料
- 未公开文件
- 内部审批稿
- 带有保密、限制传播、内部流转属性的文本
- 任何通过推断、复制、转述得到的非公开信息

---

## 一、样本收集的总原则

### 1. 真实性优先

样本必须来自明确公开来源，且可追溯。

### 2. 代表性优先

优先选取"足以代表某一类正式写法或结构模式"的材料，而不是泛泛堆数量。

### 3. 结构价值优先

优先保留那些：
- 结构清楚
- 标题层级明确
- 表达成熟
- 逻辑可复用
- 适合提炼模板的材料

### 4. 可迁移性优先

优先收集能迁移到多个任务中的样本，例如：
- 政策解读结构
- 风险分析结构
- 执行摘要写法
- PPT 页级结构

### 5. 边界清晰

样本只能帮助项目学习：
- 正式表达方式
- 公开材料分析框架
- 提纲与PPT逻辑

不能用样本去模拟：
- 某家机构的内部口径
- 某组织未公开的审稿偏好
- 某单位的隐含审批逻辑

---

## 二、推荐样本类型

建议优先收集以下 6 类。

### A. 政策与监管原文

包括但不限于：
- 正式通知
- 办法
- 指引
- 实施细则
- 问答 / 答记者问
- 官方解读

用途：
- 政策解读
- 变化提炼
- 影响分析框架
- 事实边界控制

建议标签：`policy`, `regulation`, `official-interpretation`

### B. 银行公开披露材料

包括：
- 年报
- 半年报
- 季报
- ESG 报告
- 社会责任报告
- 风险管理章节
- 公司治理 / 内控相关章节
- 管理层讨论与分析

用途：
- 学正式披露表达
- 学风险管理相关表述
- 学披露结构
- 学谨慎表达

建议标签：`annual-report`, `quarterly-report`, `risk-disclosure`, `governance`

### C. 公开研究报告

包括：
- 券商公开报告
- 行业研究材料
- 咨询/协会/研究机构公开报告
- 专题分析文章

用途：
- 学分析框架
- 学摘要组织
- 学结论与建议的对应关系

建议标签：`research`, `industry-analysis`, `topic-report`

### D. 公开解读型材料

包括：
- 对政策的正式解读
- 对行业变化的公开观察
- 对披露材料的结构化整理

用途：
- 学"从原始材料到摘要/简报"的过渡能力
- 学如何做二次整理但不越界

建议标签：`analysis-note`, `policy-brief`, `market-observation`

### E. 公开汇报型材料 / PPT 文字稿

包括：
- 可公开获取的会议发言提纲
- 演讲材料
- 公开课件文字部分
- 公开发布的专题汇报材料

用途：
- 学页标题
- 学页间逻辑
- 学观点化表达
- 学控制密度

建议标签：`ppt`, `briefing`, `speech-outline`

### F. 改写对照样本（人工构造）

允许基于公开材料构造：
- 原始公开材料摘要 → 正式简报版
- 年报章节 → 风险分析提纲
- 政策原文 → 领导汇报版摘要
- 长文 → PPT 提纲

用途：
- 作为 few-shot
- 作为测试对照
- 作为质量校准资产

建议标签：`rewrite-case`, `before-after`, `few-shot`

## 三、样本筛选标准

每份样本在进入仓库前，至少检查以下 8 项。

### 1. 来源是否明确公开

必须可回答：
- 来源是谁
- 为什么它是公开的
- 是否可以长期引用/归档

### 2. 内容是否适合本项目

满足以下至少一个：
- 适合学习正式风格
- 适合学习结构框架
- 适合学习摘要方式
- 适合学习PPT逻辑
- 适合作为测试样本

### 3. 是否存在明显宣传腔或媒体腔

如果一份文本明显偏：
- 宣传口径
- 市场营销
- 新闻稿叙事
- 口号化表达

则不应作为核心样本，只能作为反例或低优先参考。

### 4. 是否有清晰结构

优先收录：
- 标题层级清楚
- 段落分工明确
- 逻辑可拆解
- 结论与支撑对应的材料

### 5. 是否有足够信息密度

避免收录：
- 空话很多、信息很少
- 文风看似正式但没有结构价值
- 结论堆砌但无材料支撑

### 6. 是否容易引导模型误学

慎收录：
- 过度包装
- 结论过满
- 明显用词夸张
- 不区分事实与判断

### 7. 是否存在格式问题

若原始文本：
- OCR 错乱严重
- 段落丢失严重
- 标题层级混乱
- 表格/图片导致主文本不可读

则不适合作为优质结构样本。

### 8. 是否可归类

每个样本都应能归入明确类型，否则后续调用和测试会变乱。

## 四、样本目录组织建议

建议按类型 + 用途组织，而不是按来源网站组织。

### 推荐目录结构

```text
examples/
├─ policy/
│  ├─ raw/
│  ├─ cleaned/
│  └─ notes/
├─ reports/
│  ├─ annual-reports/
│  ├─ research/
│  └─ notes/
├─ ppt/
│  ├─ raw/
│  ├─ extracted/
│  └─ notes/
└─ rewrite-cases/
   ├─ policy-to-brief/
   ├─ report-to-outline/
   ├─ text-to-ppt/
   └─ polish-cases/
```

---

## 五、单个样本的命名规范

建议统一命名格式：

```
YYYY-source-type-topic-shortname.md
```

示例：

- `2025-nfra-policy-capital-management.md`
- `2024-bank-annual-report-risk-management.md`
- `2025-research-topic-real-estate-risk.md`
- `2026-ppt-briefing-policy-impact-outline.md`

要求：
- 年份在前
- 来源类型明确
- 主题简短
- 文件名可读
- 不要用中文空格或随意命名

---

## 六、每个样本必须附带元信息

建议每个样本都配一个同名 `.meta.yaml` 文件。

例如：

- `2025-nfra-policy-capital-management.md`
- 对应 `2025-nfra-policy-capital-management.meta.yaml`

推荐字段：

```yaml
title: 某政策或材料标题
source_type: policy | annual-report | quarterly-report | research | ppt | briefing | rewrite-case | other
source_name: 来源机构或来源平台
public_confirmed: true
collection_reason:
  - 风格样本
  - 结构样本
  - PPT样本
  - 测试样本
quality_score: 4
risk_flags:
  - none
tags:
  - policy
  - formal-style
  - risk-analysis
usable_for:
  - policy-brief
  - report-outline
notes: >
  该样本适合学习政策解读结构，不适合学习PPT标题。
```

## 七、样本质量评分规范

建议用 1–5 分。

| 分数 | 标准 |
|------|------|
| 5 分 | 来源可靠；结构非常清楚；表达成熟；信息密度高；非常适合复用 |
| 4 分 | 质量高；小问题不影响使用；适合进入核心样本池 |
| 3 分 | 可参考；但结构、风格或密度一般；只做补充样本 |
| 2 分 | 问题明显；容易误导模型；仅作为反例或低优先参考 |
| 1 分 | 不建议入库；除非专门用于"负面样本" |

---

## 八、建议建立正样本与负样本

建议同时维护两类样本。

### 正样本

用于学习：
- 正式风格
- 清晰结构
- 审慎表达
- 好的提纲方式
- 好的PPT逻辑

### 负样本

用于提醒模型避免：
- 媒体化标题
- 空泛建议
- 情绪化表述
- 长段文字堆屏
- 目录式PPT标题
- 结论强于材料支撑

---

## 九、样本清洗规则

样本入库前，建议做最小清洗。

### 允许清洗

- 去掉网页导航、页脚、版权声明
- 去掉明显无关广告或推荐
- 修复断行
- 统一标题层级格式
- 标出表格/图表缺失处
- 补充来源说明

### 不允许清洗

- 修改原意
- 擅自加强结论
- 擅自删除关键限定条件
- 把暧昧表述改成更强判断
- 改写为"更专业"的版本后冒充原文

---

## 十、建议的样本最小规模

### 核心样本池（最低要求）

| 类型 | 数量 |
|------|------|
| 政策/监管原文 | 8–12 份 |
| 银行公开披露材料 | 8–12 份 |
| 公开研究报告 | 6–8 份 |
| 公开汇报/PPT样本 | 4–6 份 |
| 改写对照样本 | 8–12 组 |

### 第一阶段最低可运行版本

如果时间有限，先做到：

| 类型 | 数量 |
|------|------|
| 政策类 | 4 份 |
| 披露类 | 4 份 |
| 研究类 | 3 份 |
| PPT类 | 2 份 |
| 改写对照 | 4 组 |

---

## 十一、入库时必须写清的三件事

每份样本至少回答：

1. 为什么收它
2. 它适合训练/参考什么能力
3. 它不适合拿来学什么

否则样本会越积越多，但调用时不知道该怎么用。

---

## 十二、一句话原则

不是收"看起来正式"的材料，而是收"能稳定提升结构、风格、判断边界和汇报质量"的材料。
