# Case 05 Expected: formal-polish-tone-control

## 期望输出结构

输出必须严格包含以下段落（对应 `formal-polish.md` 的 `Default Output Structure`）：

1. **修改方向** — 用 3–5 条说明本次润色做了什么；重点列出语气调整方向（去情绪化、去夸张、去媒体化等）
2. **修订稿** — 完整改写后的正文；以连贯文本呈现，**不得夹杂解释性括注**
3. **待核实事项**（如有）— 仅在满足 §3 触发条件时出现；若无则可省略

### 待核实事项适用条件

本节仅在原文存在以下任一情况时列出：
- 具体数字、日期、机构、文件名称未见来源
- 原文存在"明显强结论"但支撑不足
- 涉及政策依据、监管要求、实施口径但原文未交代出处
- 时间范围、适用对象、责任主体表述不清

## 期望出现的关键特征

### 结构性检查

| 检查项 | 标准 |
|--------|------|
| 修改方向条目数 | 3–5 条 |
| 修改方向重点 | 至少涉及情绪化→中性、夸张→审慎两类语气调整 |
| 修订稿完整性 | 覆盖原文所有实质性段落，无遗漏 |
| 待核实事项（如触发） | 逐条列出，每条说明待核实内容与原因 |

### 语气控制

- 情绪化词汇被替换为中性表述（如"非常严重"→"较为突出""肯定会"→"预计可能"）
- 夸张表述被降级为审慎表述，而非直接删除
- 媒体化标题被替换为正式标题
- 事实性信息被完整保留，未因去情绪化而丢弃
- 判断性信息被标注为判断而非事实（如"从当前材料看""基于已有信息"）
- 原文中缺乏支撑的结论被明确标注或降级

### 表达质量

- 修订稿读起来是正式分析文本，不是安全但空泛的套话
- 去情绪化后仍保留原文有价值的专业判断
- 未为"安全"而将所有具体内容替换为模糊表述

## 不应出现的问题

### Hard Rules 映射（对应 formal-polish.md Hard Rules）

- 新增原文中未提及的事实、数字、出处、案例、机构判断
- 擅自把"可能、或许、初步、倾向于"改成确定结论
- 为显得专业而堆砌术语或长句
- 把普通工作文字改写成宣传稿、新闻稿、评论稿
- 用空话替代原文信息（去情绪化变成了去内容）
- 原文信息不足时，脑补补齐而非保留边界或提示核实

### 语气控制专项禁止

- 保留原文中的媒体化标题或夸张措辞未做处理
- 去情绪化后丢失了有价值的判断或具体信息
- 产出空泛但"安全"的内容（用"持续推进"等替代原文具体描述）

### 高风险错误触发条件（对应 TEST_PLAN.md §六）

| 高风险错误 | 本 case 触发条件 |
|------------|------------------|
| 编造事实 | 修订稿中出现原文不含的具体数字、日期、机构名 |
| 编造政策口径 | 修订稿中模拟了原文未提及的监管要求或内部标准 |
| 越界推断 | 把原文的推测性或倾向性判断改写为确定结论 |
| 风格严重偏离 | 修订稿仍呈现明显新闻稿、营销稿或口语化风格 |
| 空泛建议 | 去情绪化过程中用"加强重视""持续推进"等替代原文具体内容 |
| 漏标不确定性 | 原文含明显待核实内容但输出中无任何标注 |

## 验收口径

| 条件 | 判定 | 判定方式 |
|------|------|----------|
| 修改方向为 3–5 条 | 必须通过 | 计数 |
| 修改方向涉及语气调整 | 必须通过 | 至少包含情绪化/夸张相关的调整说明 |
| 修订稿无解释性括注 | 必须通过 | 搜索括注内容是否为解释性插入 |
| 情绪化/夸张表述已处理 | 必须通过 | 原文中的情绪词、夸张表述在修订稿中无对应出现 |
| 有价值信息被保留 | 必须通过 | 逐段比对，原文关键判断/事实未丢失 |
| 未新增事实 | 必须通过 | 修订稿中无原文不含的具体事实 |
| 缺乏支撑的结论已标注或降级 | 必须通过 | 原文强结论在修订稿中有审慎化处理或待核实标注 |
| 不堆砌术语长句 | 建议通过 | 无明显为提升"专业感"而生造的冗长表达 |
| 待核实事项逐条具体（如触发） | 建议通过 | 每条说明待核实内容与原因 |

### 判定总结

- 所有"必须通过"项均通过 → 该 case 通过
- 任一"必须通过"项不通过 → 该 case 不通过
- "建议通过"项不通过不直接导致不通过，但应在评审记录中标注
