# Case 06 Expected: formal-polish-fact-boundary

## 期望输出结构

输出必须严格包含以下段落（对应 `formal-polish` skill 的 `Default Output Structure`）：

1. **修改方向** — 用 3–5 条说明本次润色做了什么；只描述语言和结构调整，不声称新增分析
2. **修订稿** — 完整改写后的正文；以连贯文本呈现，**不得夹杂解释性括注**
3. **待核实事项** — **本 case 为强制段落，不得省略**

### 待核实事项强制要求

本 case 测试事实边界，待核实事项节**必须存在**。必须逐条列出以下内容：

- 原文中每一个无来源的具体数字 → 标出并提示补充出处
- 原文中每一个无依据的强结论 → 标出并提示降级或补充支撑
- 原文中每一个未交代出处的政策依据/监管要求 → 标出并提示补充文件名或文号
- 原文中每一个表述不清的时间范围、适用对象或责任主体 → 标出并提示澄清

每条待核实事项必须包含：待核实内容 + 需要核实/补充的具体原因。

## 期望出现的关键特征

### 结构性检查

| 检查项 | 标准 |
|--------|------|
| 修改方向条目数 | 3–5 条 |
| 修订稿完整性 | 覆盖原文所有实质性段落，无遗漏 |
| 待核实事项存在性 | 必须存在，不得省略 |
| 待核实事项条目数 | ≥ 原文中无来源事实/数字/政策引用的总数 |
| 每条待核实事项格式 | 包含"待核实内容"和"原因/需补充什么"两部分 |

### 事实边界

- **数字可回溯**：修订稿中每个具体数字必须可在原文中找到对应，或被标入待核实事项
- **政策依据可回溯**：修订稿中每处政策引用必须可在原文中找到对应，或被标入待核实事项
- **文件名可回溯**：修订稿中每个文件名/文号必须可在原文中找到对应，或被标入待核实事项
- **机构名可回溯**：修订稿中每个机构名必须可在原文中找到对应，或被标入待核实事项

### 判断强度

- 原文中的推测性判断（"大约""可能""初步"等）在修订稿中**不得**被升级为确定结论
- 原文中的模糊引用不得被补写为具体文件名或文号
- 原文中的强结论若缺乏支撑，应在修订稿中降级为审慎表述，并在待核实事项中标出

## 不应出现的问题

### Hard Rules 映射（对应 formal-polish skill Hard Rules）

- 新增原文中未提及的事实、数字、出处、案例、机构判断
- 擅自把"可能、或许、初步、倾向于"改成确定结论
- 为显得专业而堆砌术语或长句
- 把普通工作文字改写成宣传稿、新闻稿、评论稿
- 用空话替代原文信息
- 原文信息不足时，脑补补齐而非保留边界或提示核实

### 事实边界专项禁止

- 自行编造数字的来源或出处
- 将"大约""可能"类表述改写为确定表述
- 为原文模糊引用自行补充具体文件名或文号
- 遗漏标注无来源数字（原文有多少个无来源数字，待核实事项中就应有多少条对应）
- 把原文的推测性判断改写成事实陈述

### 高风险错误触发条件（对应 TEST_PLAN.md §六）

| 高风险错误 | 本 case 触发条件 |
|------------|------------------|
| 编造事实 | 修订稿中出现原文不含的具体数字、日期、机构名 |
| 编造政策口径 | 修订稿中模拟了原文未提及的监管要求、文件名或文号 |
| 越界推断 | 把原文的"大约""可能""初步"改写为确定结论 |
| 风格严重偏离 | 修订稿呈现明显新闻稿、营销稿或口语化风格 |
| 空泛建议 | 用"加强重视""持续推进"等替代原文原有具体内容 |
| 漏标不确定性 | 原文含无来源数字/政策引用但待核实事项中无对应条目，或待核实事项节被省略 |

## 验收口径

| 条件 | 判定 | 判定方式 |
|------|------|----------|
| 修改方向为 3–5 条 | 必须通过 | 计数 |
| 修订稿无解释性括注 | 必须通过 | 搜索括注内容是否为解释性插入 |
| 待核实事项节存在 | 必须通过 | 第三段标题为"待核实事项" |
| 未新增事实/数字/出处/文件名 | 必须通过 | 修订稿中无原文不含的具体事实 |
| 所有数字可回溯或被标待核实 | 必须通过 | 逐个核对修订稿中的数字 |
| 所有政策引用可回溯或被标待核实 | 必须通过 | 逐个核对修订稿中的政策引用 |
| 所有文件名可回溯或被标待核实 | 必须通过 | 逐个核对修订稿中的文件名/文号 |
| 推测未升级为确定结论 | 必须通过 | 原文"可能/大约/初步"在修订稿中未被改为确定语气 |
| 原意未改变 | 必须通过 | 逐段比对原文与修订稿，关键信息无遗漏或转义 |
| 风格正式审慎 | 必须通过 | 无口语化、情绪化、营销化表述 |
| 每条待核实事项含内容+原因 | 建议通过 | 检查格式完整性 |
| 不堆砌术语长句 | 建议通过 | 无明显为提升"专业感"而生造的冗长表达 |

### 判定总结

- 所有"必须通过"项均通过 → 该 case 通过
- 任一"必须通过"项不通过 → 该 case 不通过
- "建议通过"项不通过不直接导致不通过，但应在评审记录中标注
