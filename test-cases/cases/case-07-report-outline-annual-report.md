# Case 07: report-outline-annual-report

## 目标能力

`skills/report-outline/SKILL.md` — 年报场景报告提纲生成

## 测试目的

验证 skill 能否基于银行年报的公开风险管理章节，生成结构清晰、层级合理、与材料高度相关的报告提纲，且：
- 提纲来自输入材料，而非通用模板
- 每一级提纲都能指导实际写作
- 不出现泛泛而谈的"万能模板"章节

## 输入材料

### 输入类型

bounded-input（受限输入）— 使用已有年报样本元数据引用作为材料参照，结合已有 test-cases/inputs 中的年报风险管理章节摘录。

### 输入来源

- 实际输入材料：`test-cases/inputs/case-10.input.md`（包含一段公开年报风险管理章节摘录，文件本身仅标注"公开可用文本"，未标明具体机构）
- 相邻年报元数据（仅供参考 schema 格式，不证明摘录来源）：`examples/reports/annual-reports/2024-CITIC-bank-annual-report.meta.yaml`
- 材料性质：公开年报中"风险管理"章节内容，具体机构未由摘录本身确认
- 来源机构：未明确标注（摘录文件仅写"公开可用文本"）

### 来源边界

- 本材料为公开年报风险管理章节摘录，摘录文件未标明具体机构，因此无法确认摘录来源。

- 不得将摘录中的数据或判断外推至全行业、其他银行机构或未披露信息。
- 年报数据仅代表报告期情况，不反映最新变化。
- 当前摘录自身 source_url 和 access_date 缺失，本 case 标记为 **bounded-input**，不标记为 test-ready。
- 正式升级 test-ready 前需补齐摘录自身的来源信息（机构、URL、访问日期）。

## 任务要求

1. 基于输入的年报风险管理章节内容，生成结构化报告提纲
2. 输出包含：推荐标题、核心结论/写作主线、一级提纲、二级展开建议、建议补充材料
3. 用户指定用途为"研究分析"
4. 风格偏向研究型
5. 提纲不得泛化为通用年报分析框架

## 期望输出特征

- 一级标题有明确逻辑顺序（非泛泛罗列）
- 二级展开建议具体指向输入材料中的内容
- 建议补充材料部分指出了分析还需要的额外信息
- 提纲与输入材料高度相关，不是通用年报分析模板
- 核心结论/写作主线用 1–3 句话概括
- 每个一级标题下的二级展开建议应说明"写什么""为什么写""需要什么证据"

## 不允许犯的错误

- 输出通用年报分析模板（如"一、公司概况 二、业务分析 三、财务分析 四、风险分析 五、结论与建议"），与输入材料无关
- 一级标题过于空泛（如"基本情况""相关分析"）
- 二级展开建议只是"分析XXX""研究XXX"，无具体指向
- 编造年报中未提及的风险类型或数据
- 堆砌无意义章节使提纲看起来更"完整"
- 将单一银行的披露内容外推为行业整体判断

## 人工评分重点

| 维度 | 关注点 |
|------|--------|
| 结构合理性 | 提纲层级是否清晰，逻辑是否通顺 |
| 事实忠实度 | 提纲内容是否与输入材料高度相关 |
| 风格合规性 | 表述是否正式、审慎 |
| 实用性 | 提纲是否能直接指导后续写作 |
| 边界标注 | 是否指出了需要补充的材料 |

## Out of Scope

- 不验证年报中披露数据的准确性或完整性
- 不验证提纲是否覆盖了该银行年报的所有章节（仅关注风险管理章节）
- 不要求提纲包含行业对比分析（输入材料为单一银行）
- 本 case 不用于验证 skill 对多来源材料整合的能力
